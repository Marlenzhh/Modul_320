M1: Klassendiagramm mit HAT-Beziehungen

Niveau 1Visuell*

Klassendiagramm, HAT-Beziehungen

Lernziele

Auftrag

Eines der beiden Szenarien (Hotelverwaltung oder Online-Shop) auswählen und das Klassendiagramm zeichnen. Fokus: Klassen, Attribute, Assoziationen, Aggregationen, Kompositionen und Multiplizitäten. Die Kompositionen müssen begründet werden.

Szenario 1: Hotelverwaltung

Das Diagramm ist ein Lösungsvorschlag zum Vergleichen. Laut Lernziel soll das eigene Diagramm von Hand gezeichnet werden, nicht automatisch generiert.

classDiagram
direction LR
class Hotel {
  -String name
  -String adresse
  -int sterne
}
class Zimmer {
  -int zimmernummer
  -int etage
  -double preisProNacht
}
class Badezimmer {
  -boolean dusche
  -boolean badewanne
  -boolean wc
}
class Ausstattungsgegenstand {
  -String bezeichnung
  -String seriennummer
}
class Mitarbeiter {
  -int personalnummer
  -String name
  -String funktion
}
Hotel "1" *-- "1..*" Zimmer : enthält
Zimmer "1" *-- "1" Badezimmer : besitzt
Zimmer "0..1" o-- "0..*" Ausstattungsgegenstand : hat
Hotel "0..1" o-- "0..*" Mitarbeiter : beschäftigt
BeziehungArtBegründung
Hotel - ZimmerKompositionZimmer existieren nur als Teil eines Hotels und werden mit ihm gelöscht.
Zimmer - BadezimmerKompositionDas Badezimmer gehört fest zu einem Zimmer und kann nicht allein existieren.
Zimmer - AusstattungAggregationEin Gegenstand kann einem anderen Zimmer zugeordnet werden und existiert unabhängig.
Hotel - MitarbeiterAggregationMitarbeitende bleiben gespeichert, wenn das Hotel gelöscht wird.

Szenario 2: Online-Shop

classDiagram
direction LR
class Kunde {
  -int kundennummer
  -String name
  -String email
}
class Bestellung {
  -int bestellnummer
  -Date bestelldatum
  -String status
}
class Bestellposition {
  -int menge
  -double einzelpreis
}
class Produkt {
  -int produktnummer
  -String name
  -double preis
  -int lagerbestand
}
class Lieferadresse {
  -String strasse
  -String hausnummer
  -String plz
  -String ort
  -String land
}
class Zahlung {
  -double betrag
  -Date zahlungsdatum
  -String zahlungsstatus
}
Kunde "1" -- "0..*" Bestellung : gibt auf
Bestellung "1" *-- "1..*" Bestellposition : besteht aus
Bestellposition "*" --> "1" Produkt : verweist auf
Bestellung "1" *-- "1" Lieferadresse : liefert an
Bestellung "1" *-- "0..1" Zahlung : bezahlt durch
BeziehungArtBegründung
Bestellung - BestellpositionKompositionPositionen werden mit der Bestellung gelöscht.
Bestellung - LieferadresseKompositionDie Adresse wird als eigener Bestandteil der Bestellung gespeichert und mit ihr gelöscht.
Bestellung - ZahlungKompositionEine Zahlung gehört immer genau zu einer Bestellung (0..1, erst später vorhanden).
Bestellposition - ProduktAssoziationProdukte existieren unabhängig und dürfen nicht gelöscht werden.
Kunde - BestellungAssoziationEin Kunde hat beliebig viele Bestellungen, eine Bestellung genau einen Kunden.
