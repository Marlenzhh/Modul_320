M3: Interfaces im Klassendiagramm

Niveau 3Visuell**

Vererbung, Interfaces und abstrakte Klassen in UML

Lernziele

Auftrag

Eine der Beschreibungen (A oder B) auswählen, mögliche Klassen und Interfaces identifizieren und korrekt darstellen. HAT- und IST-Beziehungen mit den richtigen Pfeilen. Lösung der Lehrperson zeigen und ins eigene Repo stellen.

Beschreibung A: Kaffee bestellen mit Zahlungsart

classDiagram
direction LR
class Bestellung {
  -List~Position~ positionen
  +addPosition(kaffee, anzahl)
  +getTotal() double
  +bezahlen(zahlungsart)
}
class Position {
  -int anzahl
  +getBetrag() double
}
class Kaffee {
  <<interface>>
  +getName() String
  +getPreis() double
}
class Zahlungsart {
  <<interface>>
  +getGebuehr(betrag) double
  +bezahle(betrag)
}
Bestellung "1" *-- "1..*" Position
Position --> Kaffee
Bestellung --> Zahlungsart
Kaffee <|.. CafeMisto
Kaffee <|.. CafeLatte
Kaffee <|.. Decaf
Zahlungsart <|.. Kreditkarte
Zahlungsart <|.. Postfinance
Zahlungsart <|.. DebitCard

Eine neue Zahlungsart oder Kaffeesorte ist nur eine neue Klasse, die das Interface implementiert. Bestellung bleibt unverändert.

Beschreibung B: Hamburger mit Decorator-Pattern

classDiagram
direction TB
class Bestellbar {
  <<interface>>
  +getBeschreibung() String
  +getPreis() double
}
class Burger {
  +getBeschreibung() String
  +getPreis() double
}
class ZutatDecorator {
  <<abstract>>
  #Bestellbar inneres
  +getBeschreibung() String
  +getPreis() double
}
class MenuAufschlag {
  Getränk und French Fries
}
Bestellbar <|.. Burger
Bestellbar <|.. ZutatDecorator
ZutatDecorator o-- Bestellbar : umhüllt
ZutatDecorator <|-- ExtraZwiebeln
ZutatDecorator <|-- ExtraSauce
ZutatDecorator <|-- ExtraBacon
ZutatDecorator <|-- MenuAufschlag

Jede Zutat umhüllt das bisherige Objekt und ergänzt Beschreibung und Preis. So gibt es keine Klassenexplosion für alle Kombinationen.
