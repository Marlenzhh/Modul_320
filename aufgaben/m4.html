M4: Eigenes Projekt: UML und Dokumentation

Niveau 4EinzelarbeitVorher besprechen**

Abstraktionen im eigenen Projekt mit UML

Lernziele

Auftrag

Eine Applikation mit Delegation, Polymorphismus und mindestens zwei Design Patterns umsetzen. Die Idee zuerst mit der Lehrperson besprechen.

  • Kurze Beschreibung: Ziel (Muss-Kriterien) und Nice-to-have
  • Skizze der Architektur als UML-Klassendiagramm
  • Anforderungen und Use Cases auflisten
  • Sequenzdiagramm für einen typischen Use Case
  • Alles in einem Markdown-Dokument im Repo. Bei KI-generierten Diagrammen die Prompts dokumentieren.

Vorgaben an das Projekt

  • OO-basiert, möglichst JVM. UI ist nicht zwingend.
  • Richtwert: mindestens 8 selbst geschriebene Klassen, mindestens 800 Zeilen Code
  • KI-Hilfe ist erlaubt, muss aber im Code deklariert werden. Komplett KI-generiert wird nicht akzeptiert.
  • Saubere Trennung: User-Interface, Logik, persistente Daten (z.B. DB)
  • Validierung von User-Input mit Exception Handling
  • Mindestens zwei Design Patterns, beschrieben und begründet
  • Interfaces werden verwendet, Vererbung wenn sinnvoll (sonst begründen)
  • Clean-Code-Regeln anwenden und im Code dokumentieren
  • SpringBoot ist möglich, falls bereits bekannt

Abgabe

  • Repository mit nachvollziehbaren Commits (ein einziger Commit führt zu Punktabzug)
  • Aktuelles Klassendiagramm und ein Sequenzdiagramm eines typischen Use Cases
  • Markdown-Dokumentation: UML, Beschreibung, umgesetzte Use Cases, Fazit zum Lernprozess
  • Lauffähige Demo bei der Lehrperson anhand der Use Cases

Vorlage: Schichten der Architektur

flowchart LR
UI["User-Interface"] --> L["Logik (Services)"]
L --> P["Persistenz (Repository, DB)"]
L -.->|wirft| E["Eigene Exceptions"]
E -.-> UI
